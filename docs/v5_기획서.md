# Naeil Tour ERP 요금 업데이트 RPA V5 기획서

> 작성일: 2026-06-11 · 문서 버전 1.0 (LOOP 1~8 의사결정 확정본)
> 작성 기준: `erp_updater` v4.0.0 코드, `fare-calculator-2026.web.app` 번들(`fare-live-merged/assets/index-BPKyZVNG.js`) 분석
> 성격: 개발자 전달용 기획서. 이 문서는 기획 산출물이며 코드 구현은 별도 작업으로 진행한다.

## 2. 배경과 문제 정의

현재 항공 요금 업데이트 업무는 다음 단계로 진행된다.

1. v4 토파스조회 탭으로 TOPAS 원문 수집 (출발편·귀국편)
2. 원문 팝업에서 전체 복사
3. 웹 계산기(fare-calculator)에 출발편/귀국편 붙여넣기 → 요금 조회
4. 박수별 결과를 복사해 엑셀 정리
5. ERP 입력용 엑셀(8열)을 만들어 v4 요금수정 탭으로 실행

2~5 단계의 다리 역할을 전부 사람이 하고 있다. 복사 누락·슬롯 뒤바뀜·엑셀 변환 실수의 여지가 있고, 같은 데이터를 세 번(팝업→웹→엑셀) 옮긴다. V5는 이 다리를 프로그램 내부 파이프라인으로 대체한다.

## 3. 목표

1. TOPAS 수집 결과가 복사/붙여넣기 없이 계산 입력으로 직접 연결된다.
2. 계산 결과가 웹 계산기와 **완전 동일**하다 (골든 테스트로 보증).
3. 계산 결과를 클릭 한 번으로 ERP 요금수정 탭에 로드한다 (실행은 사용자 검토 후 수동 시작).
4. 어느 단계에서 멈춰도 그까지의 산출물(원문·결과표)을 복사/저장할 수 있다.
5. 기존 v4 요금수정 기능은 동작 변화 없이 계승한다.

## 5. 사용자 업무 흐름

### 5.1 표준 시나리오

```
[준비] 브라우저 켜기 → TOPAS 로그인(수동) → 출발편 첫 날짜 직접 조회
[수집①] 출발편 수집 시작(AC1 횟수 입력) → AC1 10건 묶음 자동 반복 → 출발편 슬롯 채움
[수집②] 귀국편 첫 날짜 직접 조회 → 귀국편 수집 시작 → 귀국편 슬롯 채움
[계산] 노선 선택(운임·시즌 자동 로드) → 박수 선택 → 요금 조회 → 박수별 결과표
[확인] 결과표·계산 과정 검토 → 복사/엑셀 저장 (여기서 종료 가능)
[전달] ERP로 보내기 → 박수 1개 선택 → 마감 제외 알림 → 알선수익 일괄값 입력 → 요금수정 탭 로드
[실행] ERP 로그인 확인 → 표 검토 → 요금수정 시작 (자동 시작 없음)
```

### 5.2 역할 분담

| 단계 | 사용자 | 프로그램 |
|---|---|---|
| 준비 | TOPAS 로그인, 첫 날짜 직접 조회 | 디버깅 크롬 기동, 접속 확인 |
| 수집 | AC1 횟수 입력 | AC1 10건 묶음 전송, 응답 감지(최대 120초), 원문 누적·백업 |
| 왕복 | 귀국편 첫 날짜 직접 조회 | 출발편/귀국편 슬롯 자동 배치, 방향 검증 |
| 계산 | 노선·박수 선택, 요금 조회 실행 | Firestore 운임·시즌 로드(캐시 폴백), 날짜별 계산, 박수별 표 생성 |
| 검증 | 결과표·계산 과정 확인 | 마감/이상값/제외 건 정직 보고 |
| 입력 | ERP 전달 실행, 검토 후 시작 | 요금수정 형식 변환·로드, v4 RPA 루프 실행 |

### 5.3 보조 흐름

- **붙여넣기 입력**: 원문 슬롯은 일반 텍스트 입력창. RPA 수집 없이 외부에서 가져온 원문을 붙여넣어도 동일 파이프라인으로 계산된다.
- **이어서 수집**: 묶음 미완료(120초 초과)로 중단돼도 수집분은 보존되며, 잔여분만 이어서 수집할 수 있다.
- **브라우저 운용**: 디버깅 크롬 1개에 TOPAS 탭과 ERP 탭을 함께 열어 두고, 프로그램이 단계에 맞는 탭을 URL 패턴으로 찾아 제어한다. 상태바에 연결 상태를 상시 표시한다.

### 6.3 버튼 정의

| 버튼 | 위치 | 동작 |
|---|---|---|
| `브라우저 켜기` | 양쪽 탭 | v4와 동일. 탭 2에서는 TOPAS 로그인으로 |
| `출발편 수집 시작` / `귀국편 수집 시작` | 수집 섹션 | AC1 반복 수집. 슬롯에 내용 있으면 덮어쓰기 확인 |
| `원문 전체 보기` | 수집 섹션 | v4식 흰 배경 팝업 + `전체 복사하기` |
| `원문 저장` | 수집 섹션 | 수동 txt 저장 (자동 백업과 별개) |
| `요금 조회` | 계산 섹션 | 계산 실행 |
| `계산 과정 보기` | 계산 섹션 | 날짜별 디버그 팝업 |
| `복사` | 각 결과표 | TSV 복사, 1.5초간 "복사됨" 표시 |
| `엑셀 다운로드` | 결과 섹션 | 박수별 시트 엑셀 저장 |
| `ERP로 보내기` | 결과 섹션 | 전달 설정 팝업 → 요금수정 탭 로드 |
| `요금수정 시작` | 탭 1 | v4와 동일 |

수집 완료 시 동작: 팝업 없이 슬롯 배치 + 파싱 요약 갱신만 (v4의 자동 팝업은 제거, `원문 전체 보기`로 대체).

### 6.4 입력 필드

| 필드 | 형식 | 검증·보조 |
|---|---|---|
| AC1 횟수 | 정수 1~366 | "첫 조회 제외 추가 횟수" 라벨 + "= 총 N일치" 환산 병기 |
| 원문 슬롯 | 멀티라인 텍스트 | 변경 즉시 파싱 미리보기(일수·범위·방향). 파싱 0건이면 경고 배지 |
| 노선 | 검색 가능 드롭다운 | Firestore 노선 목록. 미선택 시 `요금 조회` 비활성 |
| 박수 칩 | 토글 + N박 추가(1~30) | 최소 1개 선택 |
| 알선수익 일괄값 | 정수(콤마 허용), 원 | 전달 팝업 안. 0이면 한 번 확인 |

### 6.5 팝업

**ERP 전달 팝업**
```
보낼 박수: (3박✓)(4박)(5박)  ※ 한 번에 1개
알선수익(원): [ 50,000 ] — 전체 날짜 동일 적용
전달 요약: 3박 13건 중 11건 전달
 · 기간 06-01~06-13 · 요금 230,000~510,000원
 · 마감 제외 2건: 06-09, 06-15
항공비 = 왕복요금, 나머지 요금 열은 0으로 채웁니다
            [요금수정 탭으로 보내기] [취소]
```

**계산 과정 팝업**: 출발편/귀국편 각각 `날짜 / 가용 클래스 / 시즌 / 선택 클래스 / 편도요금 / 마감여부(사유)` 표. 마감 행 회색 처리.

**원문 전체 팝업**: v4 그대로 (흰 배경·검은 글자·`전체 복사하기`).

### 6.6 헷갈림 방지 장치

1. 출발/귀국 슬롯 뒤바뀜 → 원문 출도착 공항 파싱으로 방향 자동 감지, 불일치 시 경고 + `서로 바꾸기` 원클릭
2. AC1 횟수 의미 → "첫 조회 제외" 라벨 + 총 일수 환산 병기
3. 마감 의미(좌석 소진 vs 운임 미등록) → 계산 과정 팝업에서 사유 구분
4. 제어 대상 탭 → 상태바 `TOPAS 탭 연결됨 / ERP 탭 연결됨` 상시 표시
5. 요금수정 탭 데이터 출처 → 배지 `출처: 토파스 계산 (ICN-GUM-LJ · 3박 · 11건 · 14:23)`, 엑셀 새로 불러오면 해제
6. 알선수익 단위 → `(원)` 명시, 천 단위 콤마 자동

## 8. 데이터 요구사항

### 8.1 Firestore (읽기 전용)

- 프로젝트: fare-calculator-2026 (프로젝트 ID·API 키는 웹 번들에서 추출)
- 보안 규칙이 전체 공개 읽기이므로 REST API GET으로 무인증 조회 가능 (`requests`만으로 구현)

**`fares` 컬렉션**
```
{ route: "ICN-GUM-LJ", type: "기준"|"LOW"|"HIGH",
  classCode: "Y", roundTripFare: 1040000,  // 원 단위 왕복요금
  updatedAt: "YYYY-MM-DD" }
```

**`seasons` 컬렉션**
```
{ route: "ICN-GUM-LJ", type: "기준"|"LOW"|"HIGH",
  startDate: "YYYY-MM-DD", endDate: "YYYY-MM-DD", updatedAt }
```

### 8.2 로컬 데이터

| 데이터 | 위치 | 정책 |
|---|---|---|
| 운임/시즌 캐시 | `cache/fares_snapshot.json` | 로드 성공 시마다 갱신(기준 시각 포함). 네트워크 실패 시 캐시로 계산 + 경고 |
| TOPAS 원문 백업 | `logs/topas_raw/{일시}_{노선}_{출발편\|귀국편}.txt` | 수집 완료·부분 완료 시 자동 저장. 자동 삭제 없음 |
| 실행 이력 | `logs/update_history.csv` | v4 방식 계승 |
| 설정 | `config.json` | v4 키 유지 + V5 키 추가: `firestore`(project_id, api_key), `topas_raw_dir`, `anomaly_y_ratio`(기본 0.2~1.5) 등 |

### 8.3 원문 보존 원칙

- 슬롯 원문은 표시·저장 모두 수신 그대로, 프로그램이 가공하지 않는다 (파싱은 메모리 사본).
- 이어서 수집 시 기존 원문 뒤에 이어 붙인다. 중복 블록도 원문에서는 제거하지 않고 파싱 단계에서 처리한다.
- 수집 실패·중단 시에도 그 시점까지의 원문을 슬롯과 백업에 남긴다.

## 9. 계산 정책

웹 계산기 번들에서 해독한 실제 동작을 기준으로 하며, V5는 이를 그대로 이식한다. **웹과 데스크톱의 계산 결과가 달라지면 안 된다.**

### 9.1 원문 파싱

1. 블록 시작: `AN\d{1,2}[A-Z]{3}` 패턴이 포함된 줄 (명령 echo `AN15JUNGUMICN/ALJ0916 -AC-` 포함, 대소문자 무시)
2. 연도 해석: 일+월을 **오늘 기준 미래**로 해석. 올해 날짜가 오늘보다 과거면 +1년 (v4 파서의 올해 고정 방식 대신 웹 방식 채택)
3. 가용 클래스: 공백 경계의 `[A-Z][4-9]` 토큰만 (정규식 `(?:^|\s+)([A-Z][4-9])(?!\S)`), `AC1` 문자열 제외
4. 중복 날짜 블록: 마지막 블록 우선 + 화면 경고
5. 편명 지정 조회(`/ALJ915`)가 전제. 편명 미지정 원문(여러 편 혼재) 감지 시 경고 — 검증에는 v4 `topas/availability.py`(편 단위 파서) 재활용

### 9.2 좌석 수량 기준

- **가용 = 잔여 4~9석 (4석 고정, 설정 불가)**. TOPAS 표기상 9는 "9석 이상"
- 1~3석, 0, 문자 상태코드(C/L/X 등)는 비가용

### 9.3 운임·시즌 적용

1. 편도요금 = `roundTripFare ÷ 2` (클래스 문자 기준 맵 구성. route+type+classCode 중복 문서는 마지막 우선 + 경고)
2. 시즌타입 = 출발일이 `startDate ≤ d ≤ endDate`인 **첫 구간**의 type, 미매칭이면 `기준`. 구간 겹침 발견 시 웹과 동일하게 첫 매칭 적용 + 경고 표시
3. 클래스 요금 = `시즌타입 요금 있으면 그것, 없으면 기준 요금` (클래스 단위 폴백)
4. 선택 클래스 = 가용 클래스 중 **최저가 등록 클래스**
5. 출발편·귀국편은 각각 독립적으로 시즌 판정

### 9.4 마감 판정

- 날짜 마감 = 가용 클래스 중 운임표 등록 클래스 0개 (좌석 없는 날 포함)
- 내부 대체값(기준 Y × 1.2)은 웹 호환용 내부 로직으로만 유지. **화면·복사·엑셀·ERP 어디에도 금액으로 노출 금지** (항상 "마감")
- 왕복 조합 마감 = 출발일 마감 OR 귀국일 마감
- ERP 전달 시 마감 제외 + 제외 목록 알림

### 9.5 박수 계산

- 귀국일 = 출발일 + N일 (3박 → +3일)
- 왕복요금 = 출발일 편도 + 귀국일 편도
- 귀국일이 귀국편 원문 범위에 없으면 해당 조합 제외 + 건수 요약 표시
- 표시 반올림은 JS `Math.round`와 동일 동작 (Python 은행원 반올림 금지 — `floor(x+0.5)` 구현)

### 9.6 단위

- 전 구간 **원 단위** (Firestore 저장값 = 계산 = ERP 입력 모두 원). 천원 단위 그룹운임표 변환은 웹 운임 관리 입력 단계의 일로 V5 범위 밖

### 9.7 출력 포맷

| 채널 | 포맷 |
|---|---|
| 화면 | 박수별 표: `출발일(YYYY-MM-DD) / 왕복요금(콤마+원) / 상태(공란\|마감)` — 요일 미표기 |
| TSV 복사 | 한 줄당 `YYYY-MM-DD[TAB]{숫자\|마감}`, 헤더 없음 (웹과 문자 단위 동일) |
| 엑셀 | 박수별 시트(`3박`/`4박`/…): A 출발일·B 왕복요금·C 상태 + `정보` 시트(노선·수집 일시·운임 기준 시각·백업 경로) |

### 9.8 ERP(요금수정 탭) 로드 매핑 — 단일 날짜 8열 모드

| ERP 열 | 값 |
|---|---|
| 날짜 | 출발일 |
| 항공비 | 왕복요금 (원, 그대로) |
| 알선수익 | 전달 팝업의 일괄값 |
| 호텔비·지상비·여행경비·소아·유아 | 0 |

- 마감 제외, 날짜 오름차순
- 이상치 경고: 왕복요금이 해당 노선 **기준 Y 왕복요금의 20~150% 범위** 밖이면 행 단위 경고 (기본값, config로 조정 — 미결 항목 14장)
- 0원·음수는 차단 수준 경고

## 13. 릴리스 고려사항

1. **2단계 출시**: 1차 MVP(수집+계산+출력)로 계산 정확도를 실무에서 검증한 뒤 2차(ERP 전달)를 붙인다.
2. **당분간 로컬 실행**: run_gui.bat 방식. 설치본·자동 업데이트 배포는 안정화 후 별도 결정.
3. **레포 전략**: 로컬에서 MVP를 만들어 테스트하고, 이후 기존 레포(`KAKNAKIAK/naeil-erp-updater`)로 합치는 작업은 **추후 별도 요청으로 진행** (이 기획서 범위 밖).
4. **채널 분리 원칙(설치본 전환 시)**: V5는 별도 manifest(`latest_v5.json`)와 별도 설치본 파일명(`NaeilERPUpdaterV5_Setup_x.x.x.exe`)을 사용해 v4 사용자 오업데이트를 차단한다.
5. **v4 병행**: V5 안정 판정 전까지 v4를 업무 기본 도구로 유지한다.
