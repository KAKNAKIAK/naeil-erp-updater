# Naeil ERP Updater

내일투어 ERP 항공요금 자동 업데이트, TOPAS AC1 원문 수집, 박수별 왕복요금 계산 도구입니다.

## v5.0.21

- 호텔비 수정 기간이 길어 조회 결과가 여러 페이지로 나뉠 때, 페이지 번호만 보고 저장하던 방식을 실제 행 데이터 확인 방식으로 바꿨습니다.
- 페이지 이동 후 이전 페이지 데이터가 남아 있으면 저장하지 않고 재시도하거나 안전하게 중단합니다.
- 전체 페이지 수가 확인되지 않으면 추정 실행하지 않고 중단합니다.

## v5.0.20

- 프로그램이 최소화된 상태에서 작업이 끝나도 완료·실패 팝업이 화면 앞으로 복원됩니다.
- 엑셀 파일 선택창을 메인 창에 연결하고, 파일 분석을 백그라운드에서 처리해 화면 멈춤을 줄였습니다.
- 엑셀 분석 중에는 입력과 중복 실행을 잠가 데이터가 섞이지 않도록 했습니다.
- ERP와 TOPAS의 긴 대기 구간에서 중지 요청을 확인하고, 다음 페이지 저장이 이어지지 않도록 보강했습니다.
- 엑셀 분석 중 프로그램을 종료해도 백그라운드 작업이 닫힌 화면을 다시 호출하지 않도록 정리했습니다.

## v5.0.19

## v5.0.18

- 팀출발, 예약가능, 기존 예약신청 등 다른 진행구분 행은 원래 상태를 그대로 유지합니다.

## v5.0.16

- 호텔비 수정 시 입력표의 진행구분과 관계없이 ERP에서 `대기예약(06)` 행만 먼저 `예약신청`으로 변경합니다.
- 기존 `예약신청`, 팀출발 등 다른 진행구분은 그대로 유지됩니다. `예약마감` 행은 ERP 정책대로 상태 변경과 요금 수정에서 제외됩니다.
- 대기예약에서 변경된 행의 최종 진행구분은 `예약신청`으로 유지됩니다.
- `대기 예약`, `예약 대기`, `대기예약`, `예약대기` 입력은 모두 `대기예약`(`procCd=06`)으로 처리합니다.
- 예약마감 행의 기존 ERP 동작과 요금 수정 제외 처리는 변경하지 않았습니다.

## v5.0.4

- 요금 입력표 상단에 `요금구분` 입력 필드를 추가했습니다.
- 요금수정 실행 시 ERP `행사요금일괄수정` 검색 조건의 `#priceDesc`에 요금구분 값을 넣고 조회합니다.
- 요금구분은 ERP에 저장된 텍스트 그대로 입력해야 합니다. 예: `3박_다낭` (`3박 다낭`은 다른 조건으로 조회될 수 있음)
- 빈 값이면 ERP 요금구분 조건을 비워 전체 요금구분 대상으로 조회합니다.
- `진행구분` 입력 필드 또는 요금 입력표/엑셀에 `대기예약`, `예약신청`, `예약마감`이 들어가면, 조회된 행사에 `정보일괄수정`으로 해당 진행구분을 함께 적용합니다(`procCd=06/04/05`).
- 요금 입력표의 요금 칸에 위 진행구분이 들어간 경우에도 요금 0원 저장이 아니라 진행구분 변경으로 처리합니다.
- `대기예약` 행에 호텔비 수정 금액이 함께 있으면 해당 행만 먼저 `예약신청`(`procCd=04`)으로 변경한 뒤 요금을 수정하며, 최종 상태도 `예약신청`으로 유지합니다. 다른 진행구분은 변경하지 않습니다.
- ERP 정책상 이미 `예약마감`인 행은 요금 일괄수정 대상에서 제외됩니다. 일부만 예약마감이면 RPA는 원래대로 진행하고, 전체가 예약마감이라 수정 가능한 행이 0개인 페이지는 요금 업데이트만 건너뜁니다.
- 운임/시즌 DB는 스냅샷 문서를 우선 사용해 Firestore 읽기 횟수를 줄입니다.

## Auto Update

앱은 시작 시 `config.json`의 `update_latest_url`을 확인합니다.

현재 연결된 manifest:

```text
https://api.github.com/repos/KAKNAKIAK/naeil-erp-updater/contents/latest.json?ref=main
```

배포 절차:

1. `build_setup.ps1`로 설치본을 생성합니다.
2. `release/NaeilERPUpdater_Setup_<version>.exe`를 GitHub Release asset으로 업로드합니다.
3. 루트 `latest.json`의 `version`, `download_url`, `sha256`을 최신 설치본 기준으로 맞춥니다.
4. 변경된 `latest.json`을 `main` 브랜치에 push합니다.

앱은 `latest.json`의 `version`이 현재 `APP_VERSION`보다 높을 때만 업데이트를 제안합니다.
